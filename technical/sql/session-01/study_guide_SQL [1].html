01

قاعدة البيانات إيه؟

قاعدة البيانات (Database) هي مجموعة منظمة من البيانات، بيتم تخزينها والوصول إليها إلكترونيًا من خلال نظام حاسوبي، وبتدعم تخزين البيانات والتعامل معها (إضافة، تعديل، حذف، استرجاع).

فكّر فيها كده: تخيل قاعدة البيانات كخزانة ملفات كبيرة ومنظمة، بها أدراج (Tables/جداول) لكل نوع من البيانات، وكل درج له تسميات وترتيب يسهل الوصول لأي معلومة بسرعة — بدل الاعتماد على ملفات متفرقة وغير مترابطة.

مكونات المنظومة

في 3 أطراف بتتواصل مع قاعدة البيانات من خلال نظام إدارة قواعد البيانات (DBMS): Application (برامج المستخدم النهائي)، Other Users (مستخدمين متصلين مباشرة)، وOther DBMS (أنظمة إدارة أخرى). كل دول بيتواصلوا مع الـ DBMS اللي بيعرّف السجلات، ينفّذ الاستعلامات، ويحدّث البيانات، وبعدين يخزنها في منطقة التخزين (Storage Area).

03

SQL والمعاملات (Transactions)

SQL اختصار لـ Structured Query Language، بتُستخدم لتنفيذ العمليات على السجلات: تحديث، إدراج، حذف، وإنشاء وتعديل الجداول والعروض.

مهم جدًا: SQL ليست نظام قاعدة بيانات بحد ذاتها (زي MySQL أو Oracle)، وإنما هي "لغة استعلام" بنستخدمها للتواصل مع نظام إدارة قاعدة البيانات وإصدار الأوامر له.

المعاملة (Transaction)

وحدة منطقية واحدة من عمليات قاعدة البيانات، بتشمل عملية أو أكتر من (insert / delete / update)، ممكن تكون مضمّنة في برنامج أو تُنفَّذ تفاعليًا عبر SQL.

خصائص ACID

Atomicity — الذرية
المعاملة تُنفَّذ بالكامل أو لا تُنفَّذ أبدًا (لا تنفيذ جزئي)
Consistency — الاتساق
انتقال قاعدة البيانات من حالة صحيحة إلى حالة صحيحة أخرى
Isolation — العزل
كل معاملة تُنفَّذ دون تأثر بمعاملات أخرى تعمل في نفس الوقت
Durability — الديمومة
التغييرات المحفوظة (Committed) تبقى دائمة حتى بعد أي عطل
04

مخطط قاعدة البيانات (Schema)، أنواع البيانات، والقيود

الـ Schema عبارة عن مجموعة من الكائنات (Objects) المرتبطة ببعضها داخل قاعدة البيانات، ولها مالك واحد له صلاحية التعديل على بنية أي كائن داخلها. الـ Schema لا تمثل شخصًا بحد ذاته، رغم ارتباطها بمستخدم (User) موجود في قاعدة البيانات.

أنواع البيانات (Data Types)

النوعأمثلة
نصية / حرفية (Alphanumeric)VARCHAR2, CHAR
رقمية (Numeric)NUMBER, INT, FLOAT
تاريخ ووقت (Date and Time)DATE, DATETIME

قيود قواعد البيانات (Constraints)

Primary Key
يمنع التكرار والفراغ (يجمع Not Null + Unique) — يميّز كل صف بشكل فريد
Not Null
يمنع ترك الحقل فارغًا (لا يقبل NULL)
Unique Key
يضمن أن كل القيم في العمود فريدة ولا تتكرر
Referential Integrity (FK)
يربط عمودًا بعمود آخر (غالبًا Primary Key) في جدول آخر
Check
يفرض شرطًا منطقيًا معينًا على القيم المسموح بإدخالها

06

DDL — Data Definition Language

تُستخدم لتغيير بنية الجدول: إنشاء، حذف، أو تعديل. جميع أوامرها Auto-committed ولا يمكن التراجع عنها.

create.sql
CREATE TABLE EMPLOYEE(
    Name VARCHAR2(20),
    Email VARCHAR2(100),
    DOB DATE
);
drop.sql
DROP TABLE EMPLOYEE;
alter.sql
ALTER TABLE STU_DETAILS
ADD (ADDRESS VARCHAR2(20));

ALTER TABLE STU_DETAILS
MODIFY (NAME VARCHAR2(20));
truncate.sql
TRUNCATE TABLE EMPLOYEE;
TRUNCATE مقابل DELETE: TRUNCATE مطابق وظيفيًا لـ DELETE بدون WHERE (بيمسح كل الصفوف)، لكنه أسرع لأنه مش بيسجل صف بصف، وهو أمر DDL — بينما DELETE أمر DML.
ملحوظة مهمة لو شغال على PostgreSQL: القاعدة العامة إن DDL "مش ممكن ROLLBACK" صحيحة في أغلب الأنظمة (زي MySQL/Oracle مع TRUNCATE مثلًا). لكن في PostgreSQL تحديدًا، كل أوامر DDL — بما فيها TRUNCATE وCREATE وDROP — بتكون transactional فعليًا، يعني لو نفّذتها جوه BEGIN...ROLLBACK قبل ما تعمل COMMIT، هترجع زي ما كانت. يعني الفرق ده خاص بنظام قاعدة البيانات المستخدم، مش قاعدة مطلقة في SQL كله.
07

DML — Data Manipulation Language

تُستخدم لتعديل محتوى البيانات نفسها، مش بنية الجدول. أوامرها Not Auto-committed — يمكن التراجع عنها بـ ROLLBACK.

insert.sql
INSERT INTO Students
VALUES ('Saleh', 'Ahmed', 'Moharam bak', 'Alex.');

-- أو أعمدة محددة (الباقي NULL)
INSERT INTO Students (LastName, City)
VALUES ('Hassan', 'Assuit');
delete.sql
DELETE FROM Store_Information
WHERE store_name = 'Los Angeles';
update.sql
UPDATE Students
SET Address = '241 El-haram', City = 'Giza'
WHERE LastName = 'El-Sayed';

من غير WHERE، UPDATE بيطبّق
التعديل على كل صفوف الجدول
دفعة واحدة! لازم تتأكد من
شرط WHERE قبل التنفيذ دايمًا.
08

DCL — الصلاحيات، و TCL — المعاملات

DCL بتمنح أو تسحب صلاحيات المستخدمين. TCL بتُستخدم فقط مع أوامر DML (زي INSERT وDELETE وUPDATE)، ومينفعش تتستخدم أثناء إنشاء أو حذف الجداول (DDL).

dcl.sql
GRANT SELECT, UPDATE ON MY_TABLE
TO SOME_USER, ANOTHER_USER;

REVOKE SELECT, UPDATE ON MY_TABLE
FROM USER1, USER2;
tcl.sql
DELETE FROM CUSTOMERS WHERE AGE = 25;
COMMIT;

-- أو للتراجع قبل الـ COMMIT
DELETE FROM CUSTOMERS WHERE AGE = 25;
ROLLBACK;

SAVEPOINT SAVEPOINT_NAME;
خلاصة: COMMIT بتحفظ التعديلات بشكل دائم، ROLLBACK بتتراجع عن التعديلات اللي لسه ما اتحفظتش، وSAVEPOINT بتحدد نقطة تقدر ترجعلها من غير ما تلغي المعاملة كلها.
09

مفاهيم قواعد البيانات العلائقية: ERD والمفاتيح

نموذج الكيان والعلاقة (ERD) أداة لتصميم قواعد البيانات العلائقية قبل إنشائها. القاعدة الأساسية: الكيانات (Entities) تتحول إلى جداول (Tables)، والخصائص (Attributes) تتحول إلى أعمدة (Columns). مثلًا كيان 'Book' يتحول لجدول Book بأعمدة Title, Edition, Year, Price, ISBN, Pages, Aisle, Description.

Primary Key
عمود (أو أكتر) يميّز كل صف بشكل فريد لا يتكرر (مثال: BOOK_ID في جدول BOOK)
Foreign Key
عمود في جدول يشير لمفتاح أساسي لجدول آخر، وبكده بيربط الجدولين ببعض
▸ مثال متكامل: مكتبة
AUTHOR (المؤلف)        → AUTHOR_ID كمفتاح أساسي
BOOK (الكتاب)          → BOOK_ID كمفتاح أساسي
BORROWER (المستعير)    → BORROWER_ID كمفتاح أساسي
AUTHOR_LIST (جدول ربط) → AUTHOR_ID + BOOK_ID كمفتاحين أجنبيين
COPY (نسخة الكتاب)     → BOOK_ID كمفتاح أجنبي
LOAN (الاستعارة)       → COPY_ID + BORROWER_ID كمفتاحين أجنبيين
الخلاصة: المفاتيح الأجنبية هي "الجسر" اللي بيربط الجداول المختلفة ببعض، وهي أساس فكرة "العلائقية" في قواعد البيانات، وبتمنع تكرار البيانات وتحافظ على تكاملها.
